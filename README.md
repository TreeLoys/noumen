# The Book of First Dates — Seventh Edition

**"Before Selection" · A formal theory of distinction at budgeted execution positions**

A formal account of how acts of distinguishing are executed: the position of execution, the two poles of denoumenization, the cost of verification, 27 gates, 45 laws, and 7 status journals. Written as instructions for neural nets — and as a map for anyone who wants not to *answer prettily*, but to **distinguish what is being asked, in which grammar, and at whose expense**.

## What this repository is

**Noumen** hosts the Seventh Edition of *The Book of First Dates*. This is not physics, not religion, and not a "compiler of meanings" in the machine sense (that word is a label). It is **rules for accounting acts of distinguishing** at positions that have a budget.

The seventh edition adds four key innovations:

1. **Position of execution (`this`)** — the executor is not a registry row; a program does not contain its own runtime.
2. **Two poles of every act** — noetic (the filter changed) and noematic (contrast appeared); "which pole is true" is a broken question.
3. **Cost of distinguishing** — every verification is paid for; an economy without a named budget owner is a laundromat.
4. **[TRASH] archive** — what is cut off does not vanish; extinguished for action, preserved for reflection.

## Seven journals (claim statuses)

Every claim must carry an **explicit status**. Mixing statuses — Gate 13.

| Journal | Meaning |
|---------|---------|
| **[SOLVED]** | Follows from accepted rules |
| **[CHOICE]** | Adopted as a method of construction |
| **[GIVEN]** | Premise acknowledged before construction |
| **[OPEN]** | Transition not supplied with conditions; draw nothing beyond the border |
| **[LABEL]** | Pointer-word, not a description |
| **[FRICTION]** | Cost of verification or maintenance; always with a budget owner |
| **[TRASH]** | Archive of the cut-off: configuration, selector, reason, date |

## Agent workflow (short)

```
1. Heard a claim → which question, rule, position? (§5.2)
2. "Does X exist?" → space, feature, perspective, date (§5.1)
3. Check K: non-empty? conflicting conditions? (Laws 20–21)
4. Met "cannot" → Gate 26: prohibition in G, or MU?
5. Cutting off → [TRASH] + date + selector (Gate 24)
6. Not verifying → [FRICTION] + budget owner + review date (Gate 25)
7. Applying to life/death/deity/physics → passport (Law 45)
8. Assign one of seven journal statuses — do not mix (Gate 13)
9. On doubt, run exam §6; cross-check failures in §9
```

## Application examples

### Broken vs unbroken questions

| Question | Verdict |
|----------|---------|
| "What lies in the noumenon?" | MU — not a shelf |
| "What is the path of the electron in interference?" | MU_G — "path" is outside G's domain |
| "What are simultaneous exact position and momentum?" | **Not MU** — a limitation, [SOLVED] |
| "What is death?" (without perspective) | MU; split: perspective / the real |

### Typical LLM failures (see §9)

- Answering MU to "who said yes" with K={YN,NY} — unknownness ≠ MU
- Declaring Heisenberg MU — Gate 26
- Writing `this` as a registry row — Law 37
- "AGI is possible only this way" — Gate 7; necessary ≠ sufficient
- "Life struggles against entropy" — confiscated; a pattern survives
